# 分组必须词条

专用预设的 `required_affix_groups` 使用“组间 AND、组内 OR”。例如，要
求“强化祷告 +1 或 +2”，把两个词条都选中，点击“将勾选词条加入同一
OR 组”；再为其他必须词条分别建立组。卡片会用 `★` 和组号标记这些
词条，折叠时仍显示“必须”摘要。

旧版只有 `required_affixes` 的预设仍按每个词条都必须命中处理，不会把原先只选 +2 的规则自动改成 +1 或 +2。
保存新分组时同时保留扁平 `required_affixes` 作为旧字段，新版本以 `required_affix_groups` 为准（包括空列表）。
**带 OR 分组的预设只能配合本次分组版程序使用。旧版程序不理解 OR，会把扁平列表当成 AND，可能误判为不合格；不要拿新预设回旧版执行清理。**
空组、非列表数据和不属于有效词条的组会被拒绝或安全地判为无效，不会静默丢弃要求。

启用的通用预设词条也可作为专用预设的必须词条候选。编辑器会将这类候选标明为“通用”，加入分组不会把它复制到专用词条列表；匹配时使用“启用通用 ∪ 专用”去验证要求。通用预设停用或删除后，依赖它的要求仍保留并显示为无效，直到用户把同名词条明确加入专用预设。

`data/affix_catalog.json` 是可选的、由固定来源生成的建议元数据。它只
用于显示同族候选和明确的兼容性提示；缺失、未知或名称歧义时不会阻止
手动建立分组。名称查找仅使用 Unicode NFKC 规范化，不改变 OCR 原文，
也不根据数字后缀推断同族关系。来源、ID 覆盖和类别区别见 [词条类别研究](affix-catalog-provenance.md)。

## 复仇者 兽爪：把 +2 改为 +1 或 +2

1. 打开专用预设编辑器，确保上方有效词条已勾选 `强化祷告+1`、`强化祷告+2`。
2. 在“必须词条组”列表中选中现有的 `强化祷告+2` 组。
3. 点击“加入已验证同族候选”，列表应明确显示 `强化祷告+2 或 强化祷告+1`。此按钮只加入已经选作有效词条的同族成员，不会悄悄加入未选中的基础级别。
4. 点击“保存”。卡片摘要和两个对应词条都会带上必须组标记。

也可手动在候选列表中勾选这两个词条后点击“更新选中组”。若此前没有必须组，则点击“将勾选词条加入同一 OR 组”。仅勾选候选但没有加入/更新组，不会改变已生效的规则。

```json
{
  "required_affix_groups": [["强化祷告+1", "强化祷告+2"]]
}
```

此组只满足一次要求，有效词条数按实际识别的正面词条计算，不会把两个候选算成两条。若再加一个组，则两个组都需要满足。

## 女爵 战技：引用普通通用词条

假设启用的普通通用预设包含以下词条：

- `每次打倒封印监牢里的囚犯，能提升攻击力`
- `每次打倒黑夜入侵者，能提升攻击力`

编辑普通模式的“女爵 战技”，在必须候选列表中选中这两条，加入同一个 OR 组并保存。无需把它们重复加入专用有效词条。

```json
{
  "required_affix_groups": [
    ["每次打倒封印监牢里的囚犯，能提升攻击力", "每次打倒黑夜入侵者，能提升攻击力"]
  ]
}
```

任一词条命中即可满足该组；仍需达到双有效或三有效数量要求，并满足其他必须组。这是每套预设都可使用的能力，不是针对角色名称的特殊规则。深夜模式同样可以引用启用的深夜通用词条，商店与仓库均支持。

通用词条不会自动变为必须，只对明确设置了对应组的预设生效。已有用户预设不会被自动改写。
