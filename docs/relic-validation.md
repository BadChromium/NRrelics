# 违规遗物检测

存档页的“违规遗物检测”只读取用户选择的 PC `NR0000.sl2` 副本。PC `BND4` 的
`USERDATA_10` 是全局/规制数据，不是玩家背包；验证只解密并解析玩家槽位
`USERDATA_0` 至 `USERDATA_9`。空槽也会被安全解析，结果带有 `USERDATA_n` 槽位标签，避免把
不同角色或 GUI 使用的槽位混为一个背包。实现不会创建备份、重打包、写回或删除任何存档文件。
验证也不读取游戏内尚未保存的状态，不能证明遗物的获取来源、官方有效性或无封禁风险。

结果分为三类：

- **符合已知规则**：当前数据满足本版本已实现的规则。
- **违反明确的已知规则**：命中非法 ID 范围、词条池不匹配、已知冲突、顺序错误或同一玩家槽位内
  重复唯一遗物；不同 `USERDATA_n` 玩家槽位之间的重复不会被误判为同一背包重复。
- **未知**：格式、版本、ID、特殊遗物或数据表无法安全判断。未知不会降级为合法。

结果采用与仪表盘类似的遗物卡片，只显示违反已知规则的遗物，每个角色标题只显示一次。
分组标题显示对应存档角色的玩家名称，不显示槽位编号。名称缺失时显示“未命名角色”；
内部仍按槽位分组，避免合并同名角色。每件卡片只显示颜色、收藏状态和中文正负词条，
不显示模板池 ID、判定或原因。
页面描述为“仅列出违规遗物，包括用CE修改的合法遗物（只读取不修改存档）”。
检测不能识别修改来源，也不能保证找出所有 CE 修改：满足规则的修改可能通过检测。
空词条不显示；缺失名称时显示
“未知词条（ID: …）”，不猜测名称。若非空存档中的所有遗物检查通过，显示“所有遗物都合法”；
这个简短提示仍仅表示通过当前社区规则。读取失败、没有遗物或存在未知结果时不会显示该提示。
中文名称优先使用现有词条目录，其余来自同一参考提交的 `zh_CN/AttachEffectName*.fmg.xml`，
随参数表和 MIT 许可一起打包。显示名称不参与合法性判定。

实现依据固定在 `data/relic_validation/` 的三张参数表，来源是 MIT 授权的
`alfizari/Elden-Ring-Nightreign-Save-Editor`（参考提交：
`0d2ad1494c372098e689c23159656df70ff2d76d`）。仅复制只读校验所需的数据和许可证；
参考项目的编辑器、打包器和写入逻辑没有被导入。参数覆盖不是游戏规则的完整证明，后续版本可能
需要新的审查与数据更新。
